Jev принимает состояние и набор вопросов, а возвращает короткие типизированные решения: выбор из вариантов, оценку или число. Для [моего роутера субагентов Codex](https://github.com/suenot/codex-jev-router) такое решение отвечает на вопрос, какую модель и уровень рассуждения дать следующему агенту. Среди открытых проектов ниже есть готовые локальные серверы, библиотеки для экспериментов и модель, обученная на игровых кадрах. Названия похожи, возможности заметно различаются.

## Laya

[Laya](https://github.com/NandhaKishorM/laya) делает несколько типизированных решений за один проход. У проекта есть Python-библиотека и локальный сервер с совместимым с Jev HTTP-интерфейсом. Разработчик предлагает англоязычный и многоязычный чекпойнты; последний интересен, когда краткое описание задачи для роутера написано по-русски. Поддерживается пакетная обработка. Для выбора модели Codex все равно стоит отдельно проверить точность и калибровку на собственных поручениях.

## Kev

[Kev](https://github.com/jaredpalmer/kev) предлагает семейство открытых моделей разного размера и локальный endpoint `/v1/systemone`. В README отправной точкой назван вариант 4B; крупные варианты предъявляют заметно более высокие требования к памяти. Это прямой кандидат на замену удаленного движка решений, если есть ресурсы для локального запуска. Опубликованные автором измерения относятся к его тестам и не показывают качество маршрутизации субагентов Codex.

## GLiNER2.5-Decide

[GLiNER2.5-Decide](https://huggingface.co/fastino/GLiNER2.5-Decide) классифицирует текст по меткам, заданным при вызове. Англоязычный чекпойнт имеет 340 млн параметров; есть [версия 1B](https://huggingface.co/fastino/GLiNER2.5-Decide-1B) и [многоязычная версия на 287 млн](https://huggingface.co/fastino/GLiNER2.5-multi-Decide). Через GLiNER2 и `AutoExtractor.classify_text()` можно получить несколько решений за один проход без генерации текста. Для Codex нужен адаптер: это не интерфейс Jev System One.

## JevK5

[JevK5](https://huggingface.co/alibiserikbay/JevK5) — отдельный от Kev проект на основе Qwen3.5-4B. Он считывает вероятности вариантов из логитов по протоколу SemIf, а [локальный сервер](https://github.com/allebee/jevk5) предоставляет `/v1/systemone`. Скорость и точность на поручениях Codex нужно измерить отдельно.

## GLiFormer large-v1

[GLiFormer large-v1](https://huggingface.co/knowledgator/gliformer-large-v1) — модель на базе DeBERTa с 575,6 млн параметров. Она классифицирует текст по переданным меткам и также извлекает сущности, связи и структурированные данные. Для текстового роутинга применима ее классификация; Python API потребует адаптера к Jev.

## PlayJev

[PlayJev](https://github.com/OmniJev/PlayJev) обучен выбирать действие в браузерной игре по кадру и списку допустимых ходов. Он тоже отдает вероятности выбора через `/v1/systemone`, но вход здесь визуальный и игровой. Для текстового вопроса «какому субагенту поручить поиск по файлам» нужен другой движок или новое обучение. Проект интересен как пример того, что типизированное решение может опираться на изображение, а не только на текст.

## SemIf

[SemIf](https://github.com/TheoLeeCJ/SemIf-OpenJev), ранее OpenJev, воспроизводит формат решений с помощью открытых языковых моделей. Он считывает оценки вариантов из логитов и запускается через PyTorch, MLX или llama.cpp в зависимости от среды. CLI принимает JSONL; для вызова из Codex нужен адаптер. Это способ проверить локальную маршрутизацию без отдельного специализированного чекпойнта, хотя запуск модели на каждый запрос может съесть выигрыш во времени.

## NanoJev

[NanoJev](https://github.com/TianyuCodings/NanoJev) использует небольшую основу Qwen и головы для выбора, логического ответа и оценки. В репозитории есть веса, данные и обучение, а локальный сервер принимает запросы на `/api/evaluate`. Опубликованная модель обучалась преимущественно на игровых задачах. Если применить ее к описаниям задач Codex, качество переноса придется измерить отдельно; наличие знакомого API этого не гарантирует.

## jevlike

[jevlike](https://github.com/vinnylarouge/jevlike) ближе к исследовательскому конструктору: можно обучить компактный байтовый энкодер или использовать замороженный энкодер Hugging Face и оценивать произвольные текстовые варианты. Есть CLI для обучения и предсказания. Готового доказательства, что модель правильно различит «точный поиск» и «сложную диагностику» в Codex, нет. Зато здесь можно собрать собственный датасет поручений и проверить именно такую классификацию.

## simple-jev

[simple-jev](https://github.com/featherless-ai/simple-jev) получает типизированный ответ из логитов совместимой открытой языковой модели вместо генерации JSON. Сервер предоставляет `/v1/classifier` и псевдоним `/v1/systemone`; для запуска используются Transformers и PyTorch. Результат зависит от выбранной модели и формулировки вариантов, а ее оценки нельзя автоматически считать откалиброванными вероятностями успеха. Удобный путь для пробы уже имеющейся локальной модели.

## AnyJev

[AnyJev](https://github.com/nokia-applied-research/AnyJev) предлагает три уровня настройки существующей языковой модели: исправление позиционного смещения без размеченных данных, температурную калибровку и обучаемую закрытым способом голову по скрытым состояниям. Для последних уровней нужны примеры своих задач; голова требует доступа к внутренним состояниям модели. Это полезно, если решение о профиле субагента нужно подогнать под свой поток поручений. Самый простой режим может потребовать несколько проходов модели, поэтому скорость нужно измерять.

## mini-jev

[mini-jev](https://github.com/r-ms/mini-jev) сравнивает оценку вариантов по логитам замороженной Qwen с генерацией JSON по грамматике. Репозиторий скорее учебный стенд и бенчмарк, чем готовый движок для рабочего роутера. Его оценки вариантов дают порядок предпочтения, но не гарантируют калиброванные вероятности. Он помогает понять, где вообще появляется экономия на коротком решении и когда она исчезает, например для простого булева ответа.

## open-jev от nico-martin

[open-jev от nico-martin](https://github.com/nico-martin/open-jev) запускает типизированные решения в браузере через Transformers.js и WebGPU либо WASM. Есть TypeScript API `OpenJev.load().decide()` и несколько поддерживаемых моделей, включая варианты Kev. Если задача состоит в локальном выборе прямо в веб-приложении, это интереснее серверного Python-процесса. Для Codex нужен мост через Node; первый запуск также включает загрузку весов.

## minojev

[minojev](https://github.com/zeredy879/minojev) сочетает замороженную Qwen3-1.7B с небольшой обучаемой головой решений. Он принимает типизированные вопросы через локальный `/score`, публикует веса и данные и может работать на CPU. Авторы также показывают ухудшение на задаче вне обучающего распределения. Поэтому перед использованием в роутере Codex я бы собрал отдельную проверку на реальных поручениях, а не переносил опубликованную метрику.

## Open-Jev от Zefan-Cai

[Open-Jev от Zefan-Cai](https://github.com/Zefan-Cai/Open-Jev) выпускает обученные варианты 2B, 9B и 27B с головой решений и калибровкой. Локальный сервер поддерживает `/v1/systemone`; в репозитории есть данные и инструменты обучения. Из трех проектов со схожим названием этот ближе к готовой линейке моделей, но стоимость запуска сильно зависит от выбранного размера. Его результаты бенчмарка также нельзя без проверки переносить на выбор моделей субагентов.

## open-jev от daseinlabs

[open-jev от daseinlabs](https://github.com/daseinlabs/open-jev) оценивает варианты на Gemma 3 4B, повторно используя общий префикс и пакетную обработку. Есть локальные `/score` и `/v1/systemone`, реализации для MLX на Mac и PyTorch на других платформах, а также обучение головы под свою задачу. Веса Gemma требуют принятия условий доступа на Hugging Face. Это практичный вариант для эксперимента на Mac, если уже есть локальная модель и хочется проверить скорость полного маршрута.

## Сравнение на fast-decisions

На [странице GLiNER2.5-Decide](https://huggingface.co/fastino/GLiNER2.5-Decide) Fastino приводит точность полного совпадения на [fast-decisions](https://huggingface.co/datasets/fastino/fast-decisions): 17 англоязычных доменов, по 300 отложенных примеров в каждом. Текст и наборы меток одинаковы для всех моделей. Это результаты авторов, а не моя независимая проверка.

| Модель | Среднее |
|---|---:|
| [GLiNER2.5-Decide (340M)](https://huggingface.co/fastino/GLiNER2.5-Decide) | 60.2% |
| [GLiNER2.5-Decide-1B](https://huggingface.co/fastino/GLiNER2.5-Decide-1B) | 59.6% |
| [JevK5](https://huggingface.co/alibiserikbay/JevK5) | 57.6% |
| [GLiNER2.5-multi-Decide (287M)](https://huggingface.co/fastino/GLiNER2.5-multi-Decide) | 56.7% |
| [SemIf](https://github.com/TheoLeeCJ/SemIf-OpenJev) (Qwen3.5-4B) | 56.4% |
| [GLiFormer large-v1](https://huggingface.co/knowledgator/gliformer-large-v1) | 49.0% |
| [Laya Router](https://github.com/NandhaKishorM/laya) | 46.6% |

Открытые файлы содержат по 100 примеров для разработки на домен; оценки относятся к отдельному отложенному набору. Эти результаты не показывают точность выбора моделей Codex на моих задачах или русских текстах.

## Что выбрать для Codex

Если нужен локальный endpoint с привычным форматом, я бы начал с Laya, Kev, JevK5, simple-jev или одного из серверных Open-Jev. Для собственного обучения интереснее NanoJev, jevlike, AnyJev и minojev. SemIf и mini-jev помогают разобраться, сколько дает сам способ получения короткого ответа. PlayJev решает другую, визуальную задачу. GLiNER2.5-Decide и GLiFormer стоит проверять как классификаторы с собственным адаптером.

Мой [Codex Jev Router](https://github.com/suenot/codex-jev-router) поддерживает несколько этих движков через адаптеры, но совместимый интерфейс еще не означает одинаковую точность или экономию. Перед заменой движка я проверяю полную стоимость решения вместе со временем запуска, ошибками выбора и ценой последующего субагента. Пока открытых измерений именно на моем потоке задач для сравнения всех шестнадцати проектов нет.
