# Как использовать graphify с Claude Code

[graphify](https://github.com/safishamsi/graphify) превращает репозиторий в граф файлов, сущностей и связей. Вместо просьбы к агенту прочитать большой модуль целиком можно запросить у графа небольшой фрагмент, связанный с вопросом. Это удобно в незнакомом коде или при возвращении к проекту после долгого перерыва.

Моя настройка лежит в [suenot/claude-code-token-savers](https://github.com/suenot/claude-code-token-savers), в папке `graphify/`. В ней извлечение связей вынесено к отдельному провайдеру, а Claude Code запрашивает готовый граф в основной сессии. Провайдеры, ID моделей, цены и лимиты меняются, поэтому не стоит воспринимать эту схему как постоянный рецепт экономии.

## Настройте провайдера для извлечения связей

`graphify` нужен конфиг провайдера для извлечения связей. Этот пример отправляет совместимые запросы через OpenRouter. Ключ храните в переменной окружения, а не в файле.

```json
{
  "openrouter": {
    "base_url": "https://openrouter.ai/api/v1",
    "default_model": "YOUR_CURRENT_MODEL_ID",
    "env_key": "OPENROUTER_API_KEY",
    "model_env_key": "GRAPHIFY_OPENROUTER_MODEL",
    "temperature": 0,
    "max_tokens": 16384,
    "vision": false
  }
}
```

Положите конфиг в `~/.graphify/providers.json` и выберите модель из актуального каталога провайдера. После `graphify install` проверьте порядок извлечения: установка и обновления могут заменить `~/.claude/skills/graphify/SKILL.md`. В этой настройке при наличии ключа сначала используется OpenRouter, затем Gemini, а Claude-субагенты остаются запасным вариантом.

## Установите локальные компоненты

Для примера нужны [`uv`](https://docs.astral.sh/uv/) и `OPENROUTER_API_KEY`. Скрипт в репозитории устанавливает graphify, копирует вспомогательные скрипты и применяет локальные патчи:

```bash
cd graphify
./setup.sh
```

Ручной путь полезен, если хочется проверить каждый шаг. Он устанавливает `graphifyy` с дополнением OpenAI, записывает конфиг провайдера, копирует помощники в `~/.graphify/` и запускает `graphify install --platform claude`. Перед запуском читайте текущую версию скрипта: имена пакетов, поведение установки и патчи могут меняться.

## Обновляйте граф без неожиданных индексаций

Настройка может зарегистрировать хук `SessionStart`, который запускает `build-and-watch.sh`. Если граф уже есть, хук запускает `graphify watch`; если нет, он предлагает вручную выполнить `/graphify .`. Это защищает от индексации большой директории, которую вы открыли случайно.

В `~/.claude/settings.json` нужно добавить хуки, не заменяя файл целиком:

```
SessionStart  -> ~/.graphify/build-and-watch.sh
SessionEnd    -> ~/.graphify/stop-watch.sh
```

Помощники в этой настройке также пропускают слишком широкие или рискованные пути, учитывают `.graphify-skip` и имеют выключатель `~/.graphify/disable-autowatch`. Блокировка и проверка PID помогают оставить один watcher на проект. `watch` работает с кодом и AST, а документацию при необходимости обновляйте через `/graphify . --update`.

## Считайте вывод графа данными для проверки

В граф может попасть не только структура кода. Прежде чем добавлять `graphify-out/` в коммит, изучите его содержимое.

В локальной настройке есть несколько защитных мер:

- проверка чувствительных данных в graphify обрабатывает распространенные секретные файлы;
- необязательный маркер `no-media` исключает медиа из обработки;
- `patch-merge-ignore.py` меняет локальную обработку игнорирования: `.gitignore` и `.graphifyignore` объединяются, а не перекрывают друг друга;
- `precommit-graph-guard.sh` проверяет, не попали ли игнорируемые файлы в `graphify-out/graph.json`, и может остановить коммит.

Эти проверки снижают риск, но не заменяют просмотр сгенерированного вывода. Относитесь к `git commit --no-verify` как к осознанному исключению, а не обычному способу обойти проверку.

## Запрашивайте граф

Соберите граф один раз, затем задавайте узкие вопросы:

```bash
/graphify .
/graphify . --update
/graphify query "где валидируется токен и что это вызывает"
/graphify query "..." --dfs
/graphify query "..." --budget 1500
```

graphify также умеет создавать HTML, GraphRAG JSON, `GRAPH_REPORT.md`, MCP-сервер и wiki-представление. Удобная привычка проста: сначала запросите у графа узкий путь, затем откройте исходные файлы, на которые он указывает. Граф помогает исследованию, но не заменяет чтение кода, который вы меняете.

После обновления graphify снова запустите `./setup.sh` и проверьте приоритет провайдеров и локальные патчи. Конфигурация в `~/.graphify/`, хуки Claude и хуки репозитория могут сохраниться, но установленные файлы пакета могут быть заменены.

Связанный процесс разобран в [гайде по экономии токенов](https://www.suenot.com/blog/saving-tokens-llm/).
