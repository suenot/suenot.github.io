# Clother: отдельные запускатели Claude Code для разных провайдеров

Работа с несколькими провайдерами моделей в Claude Code легко превращает конфигурацию командной оболочки в беспорядок. Base URL и токен, которые были нужны для одного эксперимента, остаются в окружении, а следующая сессия незаметно уходит не в тот endpoint.

[Clother](https://github.com/jolehuit/clother) решает именно эту проблему запуском. Он стартует настоящий процесс `claude` с переменными окружения выбранного провайдера. Настройки действуют на этот процесс, а не становятся постоянной правкой командной оболочки или `~/.claude`.

В этом и польза. Можно проверить провайдера в одном терминале, пока другой сохраняет прежнюю настройку. Но это не делает API провайдеров одинаковыми и не делает непроверенный endpoint безопасным.

## Начните с именованного профиля

Clother использует запускатели `clother-<provider>` для встроенных профилей и общий запускатель для профилей, которые вы добавляете сами. Актуальный README проекта это источник истины для имен, установки и формата конфигурации. Списки провайдеров и модели по умолчанию меняются слишком часто, чтобы переносить старый список в алиасы командной оболочки.

Безопасный порядок короткий:

```bash
clother info <provider>
clother test
clother-<provider>
```

Прочитайте разрешенные endpoint и модель до запуска. Сначала выполните небольшую задачу. Если провайдер не понимает вызовы инструментов, системные промпты, потоковый вывод или формат рассуждений, который ожидает клиент, обертка не исправит несовместимость протокола.

## Храните секреты вне профиля

Используйте переменные окружения или менеджер секретов для API-ключей. Поле конфигурации вроде `api_key_env` должно содержать имя переменной, а не сам ключ. Проверьте права доступа к локальному файлу секретов, если инструмент его создает.

То же относится к пользовательским endpoint. URL на localhost может вести к локальной модели, шлюзу или туннелю к внешнему сервису. Проверьте весь путь запроса, прежде чем считать сессию локальной.

## Осторожно с разрешениями и продолжением сессий

Clother может передать обычные флаги Claude Code запущенному клиенту. Режимы с пропуском проверок разрешений удобны для одноразовых пакетных задач и рискованны в основном репозитории. Используйте их только после выбора ограниченной рабочей области и точки проверки.

Продолжение разговора между провайдерами требует такой же осторожности. В расшифровке могут быть данные вызовов инструментов или рассуждений, зависящие от провайдера. Сверяйтесь с актуальной документацией Clother и изучайте сессию, прежде чем ожидать от продолжения поведения нативного запуска.

## Когда обертки достаточно

Clother подходит, когда вы хотите сохранить официальный рабочий процесс Claude Code и явно выбирать провайдера для каждого терминала. Если команде нужны общие квоты, журналы аудита, правила маршрутизации или единая политика секретов, это задача шлюза или операционного слоя, а не скрипта запуска.

В ежедневной работе держите профили короткими и понятными, проверяйте каждый после изменения и оставляйте обычную команду Claude Code для процесса, которому доверяете. О цене и контексте также есть [гайд по экономии токенов](/blog/saving-tokens-llm).
